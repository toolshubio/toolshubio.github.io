What Is a Canonical Tag?


Duplicate content is rarely about copying — it is about plumbing. E-commerce filters (?color=red&size=m), tracking parameters (?utm_source=newsletter), HTTP vs HTTPS, www vs non-www, and print-friendly versions all create multiple URLs showing the same content. To Google, each URL is a separate page competing with itself, splitting ranking signals across copies.


The canonical tag resolves this. Placed in the page's <head>, it says: "of all the URLs showing this content, this one is the primary — consolidate everything here." It is a strong hint rather than a command; Google honors it in the vast majority of cases, provided your other signals (sitemaps, internal links, redirects) agree with it.


A common misunderstanding: canonical tags do not redirect users. Visitors still land on whichever URL they clicked; the tag only guides search engines behind the scenes. For actually moving traffic, you want a 301 redirect — canonicals are for the cases where multiple URLs must legitimately keep working.


How to Use the Canonical Tag Generator


Paste the URL you want search engines to treat as primary — the clean version, no tracking parameters, HTTPS, your preferred www choice. The generator normalizes it (stripping UTM tags, fixing the protocol, handling trailing slashes) and outputs the ready-to-paste tag:


<link rel="canonical" href="https://example.com/your-page/" />


Copy that line into the <head> section of every duplicate or variant page, pointing them all at the same primary URL. If you use WordPress, SEO plugins like Rank Math and Yoast have a canonical URL field per post — paste it there instead of editing code. Then verify in Google Search Console's URL Inspection tool that Google sees the tag.


Include a self-referencing canonical on the primary page itself — the page pointing at its own URL. Google's own engineers recommend this; it guards against scrapers and parameter variants you have not thought of yet.


How Canonicalization Works


The mechanism is a negotiation between your signals and Google's judgment.


Step 1 — Tag placement. Each variant page carries the canonical tag in its HTML head (or, for non-HTML files like PDFs, in the HTTP Link header) naming the preferred URL.


Step 2 — Crawling. Googlebot fetches the variants, reads the tags, and groups the URLs into a duplicate cluster.


Step 3 — Signal consolidation. Ranking signals — links, relevance, freshness — from all cluster members are folded toward the canonical URL. This is the payoff: instead of four weak copies, you have one strong page.


Step 4 — Index selection. Google typically indexes the canonical URL and drops the variants from results. If your sitemap, internal links, or redirects contradict the tag, Google may pick a different canonical — consistency across signals is what makes the hint stick.


Normalization is the generator's real value-add: absolute HTTPS URLs without tracking parameters get honored far more reliably than relative URLs or parameter-laden ones.

Frequently asked




Is this canonical tag generator free? 
Yes — free with no account required.


Where do I put the canonical tag? 
Inside the <head> section of the page's HTML, on every variant page — each one pointing to the primary URL.


Should the primary page have a canonical tag too? 
Yes — a self-referencing canonical (the page pointing to itself) is recommended even when no duplicates exist.


Canonical tag vs 301 redirect — which should I use? 
Use 301s when old URLs should stop working (site moves, deleted pages). Use canonicals when variants must stay live (tracking params, filters, syndication).


Can I use relative URLs in canonical tags? 
You can, but absolute URLs (full https:// address) are honored more reliably. Always generate absolute.


How long until Google respects my canonical? 
Usually days to a few weeks after recrawling. Check the "Google-selected canonical" in Search Console's URL Inspection to confirm.


What if Google ignores my canonical tag? 
Check for conflicting signals — sitemap URLs, internal links, and redirects should all agree with the tag. Mixed signals are the usual cause.
