What Is a Website Speed Test?

A speed test loads your page the way a visitor's browser would and measures what matters: how fast the main content appears, how quickly the page responds to input, and how stable the layout is while loading. The headline metrics are Google's Core Web Vitals: LCP (Largest Contentful Paint) — how fast the largest visible element renders; INP (Interaction to Next Paint) — how responsive the page feels during clicks and taps; and CLS (Cumulative Layout Shift) — how much the layout jumps around while loading. Google uses all three as ranking signals.

Good tests report two kinds of data. Field data comes from real Chrome users over the past 28 days (the Chrome User Experience Report) — this is what Google actually ranks on. Lab data comes from a controlled simulated test — useful for diagnosing problems on new or low-traffic pages where field data does not exist yet. The best free tools (PageSpeed Insights at pagespeed.web.dev) show both, for mobile and desktop separately, plus a list of specific fixes with estimated time savings.

How to Use the Website Speed Test

Running the test is easy; reading it correctly is the skill.

Enter your page's full URL and run the test — it takes 10–30 seconds. Check the mobile tab first: Google uses mobile-first indexing, and mobile scores are almost always worse than desktop. Look at the Core Web Vitals assessment badge — Pass or Fail — then the individual numbers: LCP should be 2.5 seconds or under, INP 200 milliseconds or under, CLS 0.1 or under.

Then read the diagnostics below the scores. The tool lists specific opportunities — unoptimized images, unused JavaScript, render-blocking resources, missing text compression — each with an estimated savings. Work the list in order of impact, not ease: a 2-second image fix beats five 50-millisecond script tweaks. After each round of fixes, re-run the test to confirm the improvement in lab data.

For the real verdict, check Google Search Console's Core Web Vitals report (Experience section) a few weeks later. It shows field data across your URLs, grouped by issue — that is the measurement that actually moves rankings, and it updates over a rolling 28-day window.

The Three Core Web Vitals, Plainly

LCP — Largest Contentful PaintWhen the main content becomes visible≤ 2.5s2.5–4.0s> 4.0s
INP — Interaction to Next PaintHow fast the page responds to clicks/taps≤ 200ms200–500ms> 500ms
CLS — Cumulative Layout ShiftHow much the layout jumps while loading≤ 0.10.1–0.25> 0.25

The common fixes map neatly to metrics: LCP is usually images (compress them, convert to WebP, never lazy-load the hero) and slow servers (TTFB — time to first byte — is often a hosting problem). INP is usually heavy JavaScript — defer non-essential scripts and audit plugins. CLS is usually images without width/height attributes and ads or widgets loading without reserved space. Fix in the order LCP → INP → CLS and you will cover the biggest ranking impact first.

Who Uses Website Speed Tests?

Site owners run them to find out why traffic or conversions dipped — speed regressions are silent killers.

Developers use them at every deploy, catching the chat widget or tracking script that tanks performance before it ships.

E-commerce managers test product and checkout pages, where every extra second of load time measurably costs sales.

Bloggers check their themes and plugins — a bloated theme is the most common speed problem on WordPress.

SEOs include speed in every technical audit, since Core Web Vitals are a direct ranking signal and clients understand "your site is slow" better than most findings.

Frequently asked

What is a good website speed?

Aim for LCP under 2.5 seconds, INP under 200 milliseconds, and CLS under 0.1. Those are Google's "Good" thresholds for Core Web Vitals — the band where speed stops costing you rankings.

Does page speed affect SEO?

Yes — Core Web Vitals are a direct Google ranking signal. Beyond that, slow pages lose visitors before they convert: speed affects both rankings and revenue.

What is the difference between field data and lab data?

Field data comes from real Chrome users over 28 days and determines your ranking signal. Lab data comes from a controlled instant test and is best for diagnosing problems. Fix using lab data; judge using field data.

Why is my mobile score worse than desktop?

Phones have slower processors, slower networks, and smaller screens — the test simulates a mid-range device on a mobile connection. Since Google ranks on mobile experience, the mobile score is the one that matters.

What is TTFB?

Time To First Byte — how long your server takes to start responding. It is mostly a hosting problem, not a code problem. A slow TTFB on shared hosting often means an overloaded server.

Will the test work on a new site with no traffic?

Lab data works immediately — you get a full diagnostic. Field data appears once enough real Chrome users visit, which can take weeks on a new site. Use lab data until then.

Why did the test fail for my site?

Usually the URL is unreachable: the site blocks crawlers, requires a login, is not publicly reachable, or is extremely slow to respond. Double-check the full URL and try again.

Is this speed test free?

Yes — Google's PageSpeed Insights is free with no signup, and most third-party speed tools offer free tiers.
