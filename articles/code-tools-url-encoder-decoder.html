What Is URL Encoding?

URL encoding — also called percent-encoding — rewrites unsafe characters as a % followed by two hexadecimal digits. A space becomes %20, an ampersand becomes %26, a question mark becomes %3F. Non-ASCII characters like é or 中 are first converted to their UTF-8 bytes, and each byte gets its own %XX sequence.

Why the fuss? Because certain characters have jobs in a URL. The ? starts the query string, & separates parameters, = joins keys to values. If your search term itself contains an ampersand — say you're searching for "salt & pepper" — the raw & would be read as a parameter separator, splitting your search into two broken pieces. Encoding it as %26 tells every browser and server: this is data, not structure.

Decoding is the reverse trip: turning hello%20world back into hello world so you can read what a link actually contains — useful when you're debugging redirects, inspecting shared URLs, or auditing what parameters a page is passing around.

The mode choice is the one decision that matters. Component encoding escapes everything with a structural job — ?, =, &, / all get encoded — because inside a single value, none of them are structure. Full-URL encoding preserves those characters so your address keeps working. Encoding a whole URL in component mode breaks it; encoding a parameter value in full-URL mode leaves dangerous characters raw.

Notice the pattern: component mode encodes the structural characters (:, /, ?, =, &) while full-URL mode leaves them alone. The rule of thumb: encoding a value someone typed into a form or a search box? Component. Encoding a complete link you want to keep clickable? Full URL.

One more encoding you'll meet: spaces as +. In HTML form submissions (application/x-www-form-urlencoded), spaces are traditionally written as plus signs rather than %20. Most decoders handle both, but if you're decoding form data and seeing literal plus signs, that's why — the tool's "treat + as space" option covers this case.

Frequently Asked Questions

Is this URL encoder decoder free?

Yes — free, no signup, unlimited use.

What's the difference between encode component and encode full URL?

Component encoding escapes structural characters (?, &, =, /) — use it for a single value. Full-URL encoding preserves them — use it for a complete address.

Why is there a %20 in my URL?

That's an encoded space. Spaces aren't allowed raw in URLs, so they're written as %20 (or + in form data).

What does %26 mean?

An encoded ampersand (&). It appears when the ampersand is data inside a value rather than a parameter separator.

Should I encode the whole URL or just the parameters?

Just the parameter values, with component encoding. Encoding a whole URL with component mode breaks its structure.

Is URL encoding the same as encryption?

No. Encoding only changes the representation so characters travel safely — anyone can decode it. It adds zero security.

Why do I see + instead of %20 sometimes?

HTML forms traditionally encode spaces as +. Both mean "space"; use the "treat + as space" option when decoding form data.

Is my data uploaded anywhere?

No. Encoding and decoding run entirely in your browser using its built-in functions.
