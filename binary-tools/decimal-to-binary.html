What Is a Decimal to Binary Converter?

Decimal is our everyday base-10 system (digits 0–9); binary is the base-2 system computers actually run on (digits 0–1). Converting from decimal to binary means rewriting a number so that each digit is a power of 2. The number 13 becomes 1101, because 8 + 4 + 0 + 1 = 13. The number 255 becomes 11111111 — eight ones, the largest value a single byte can hold.

The standard technique is repeated division by 2: divide the number, write down the remainder, keep dividing the quotient, and read the remainders backward. It is simple but tedious past a couple of digits, which is exactly why the tool exists. Students meet this method in computer science classes; network engineers use it on subnet masks; embedded developers use it on register values.

One thing worth knowing: binary has no concept of fractions in this tool's world. It converts integers — whole numbers. That is fine for the use cases it serves, from exam practice to debugging hardware flags.

How Decimal to Binary Conversion Works

Two methods do the same job; knowing both makes manual conversion much less error-prone.

Method 1 — Repeated division by 2. Divide the number by 2, record the remainder (0 or 1), repeat with the quotient until it reaches 0, then read the remainders from bottom to top. Example with 13: 13÷2=6 r1, 6÷2=3 r0, 3÷2=1 r1, 1÷2=0 r1 → read upward: 1101.

Method 2 — Subtract powers of 2. Find the largest power of 2 that fits, write 1, subtract, and repeat with the remainder. Example with 57: 32 fits (remainder 25), 16 fits (remainder 9), 8 fits (remainder 1), 4 no, 2 no, 1 fits → positions 32,16,8,4,2,1 become 1,1,1,0,0,1 = 111001.

A longer worked example — 184: ÷2 chain gives remainders 0,0,0,1,1,1,0,1 from top to bottom; read bottom-to-top: 10111000. Check: 128 + 32 + 16 + 8 = 184. The tool runs this same division loop in microseconds and never reads the remainders upside down.

Frequently asked

Is this decimal to binary converter free?

Yes — free, no account, no limits.

How do I convert decimal to binary manually?

Divide by 2 repeatedly, record each remainder, and read the remainders from bottom to top. For 13: 13÷2=6 r1, 6÷2=3 r0, 3÷2=1 r1, 1÷2=0 r1 → 1101.

What is 255 in binary?

11111111 — eight ones, the maximum value of one byte.

Why is my binary missing leading zeros?

Leading zeros add nothing to the value, so 13 is just 1101. Add them yourself (00001101) when you need a full byte.

Can it convert negative numbers?

Many tools show two's complement, the standard signed representation — so -5 appears as its 8-bit form 11111011.

What is the binary for 0?

Simply 0.

Is my data secure?

Yes. Conversion happens entirely in your browser — your numbers never leave your device.

What is the difference between decimal to binary and decimal to hex?

Both rewrite the same number in another base. Binary uses base-2 (longer strings), hex uses base-16 (compact). 255 is 11111111 in binary and FF in hex.
