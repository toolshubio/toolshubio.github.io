What is Percent Encoding?

URL encoding, also known as percent-encoding, is a mechanism for encoding information in a Uniform Resource Identifier (URI). Characters that are not allowed in a URL must be encoded so that they can be transmitted safely over the internet.

Common Encoded Characters

  • Space becomes `%20` or `+`
  • & becomes `%26`
  • ? becomes `%3F`
  • = becomes `%3D`

What URL Encoding Is

URL encoding (also called percent-encoding) replaces any character that isn't safe in a web address with a % sign followed by two hexadecimal digits representing the character's code. A space becomes %20, an ampersand becomes %26, a question mark becomes %3F. Non-ASCII characters — accented letters, Chinese, Arabic, emoji — are first converted to their UTF-8 bytes, and each byte is percent-encoded, so a single Chinese character can expand to nine encoded characters.

Why does this matter? Because characters like &, =, ?, and # have structural jobs inside a URL: & separates query parameters, # starts a fragment. If your search term contains a literal & ("fish & chips"), the server reads it as a parameter separator and your query breaks in half. Encoding turns the data & into %26 — inert data instead of structure — and the link survives intact.

encodeURIComponent vs encodeURI

This is the distinction that causes most encoding bugs, and the tool offers both methods because they solve different problems:

MethodWhat It EncodesUse It For
encodeURIComponentEverything except A-Z a-z 0-9 - _ . ! ~ * ' ( )A value inside a URL — query parameters, path segments, form data
encodeURIOnly unsafe characters; preserves :// / ? # & =A whole URL that already has structure

In practice:

encodeURIComponent("hello world & goodbye")
→ hello%20world%20%26%20goodbye

encodeURI("https://example.com/search?q=hello world")
→ https://example.com/search?q=hello%20world

Notice the difference: the component encoder escaped the & (it's data), while the full-URL encoder left ://, ? and = alone (they're structure). Use the wrong one and you either break the URL's structure or leave dangerous characters unescaped. When in doubt: encoding a piece of a URL → component; encoding a complete address → full URL.

A note on the plus sign: in HTML form data (application/x-www-form-urlencoded), spaces are traditionally written as + rather than %20. When decoding form submissions, treat + as a space; when encoding for general URLs, %20 is correct. Mixing these up is a classic source of "why is there a plus in my search term" bugs.

Frequently Asked Questions

What is percent-encoding?

Writing a character as % plus two hexadecimal digits (e.g., space → %20, & → %26). It lets URLs safely carry characters that would otherwise break their structure.

When should I use encodeURIComponent vs encodeURI?

Use encodeURIComponent for a value inside a URL (query parameters, path segments) — it encodes everything structural. Use encodeURI for a complete URL — it preserves ://, /, ?, &, and =.

Why did my link break when it contained an &?

The server read your literal & as a query-parameter separator, splitting your value in two. Encode it as %26 so it's treated as data.

What is the difference between + and %20 for spaces?

In HTML form data, + traditionally represents a space. In general URLs, %20 is correct. When decoding form submissions, convert + back to spaces.

How are non-English characters encoded?

They're converted to UTF-8 bytes first, then each byte is percent-encoded. One Chinese character typically becomes nine encoded characters (e.g., %E4%B8%8A).

Can I decode a URL to read its parameters?

Yes — paste the encoded URL and decode it. Percent sequences revert to readable characters, revealing the actual query values and redirect targets.

Is URL encoding the same as encryption?

No. Like Base64, it's a reversible encoding with no key and no security — anyone can decode it. It exists for safe transport, not secrecy.

Yes — free, no signup, and nothing you paste leaves your browser.
